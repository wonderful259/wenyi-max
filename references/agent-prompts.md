# 子代理提示词模板

长书（> 1.5 万词）把单章翻译和审校交给子代理，主代理只负责编排和核验，避免主上下文被正文撑爆。把 `{…}` 替换成实际值后整段作为子代理的任务说明。`{SKILL}` = 本 skill 目录的绝对路径，`{P}` = 项目目录的绝对路径。

- Claude Code：Agent 工具，subagent_type 用 general-purpose。
- 其他 agent：用各自的子任务/子代理机制。
- 不支持子代理：主会话自己按模板步骤执行，模板里「最终回复」的内容改为自己记下来。

模板里的「读取 / 写入 / 编辑文件」用你环境里的文件工具或 shell 命令完成均可。

---

## T1 · 章节梗概（阶段 1，可并行，每个子代理负责 3–6 章）

```
你是小说/报道的章节梗概撰写人。为下列章节各写一份中文梗概，不超过 200 字。

项目目录：{P}
负责章节：{chNN 列表}

对每一章：
1. 读取 {P}/chapters/chNN-en.md（⟦N⟧ 是段落标记，<N> 是格式标签，忽略它们）
2. 写梗概：关键情节/论点推进、出场人物及处境、重要信息和转折。人物名用音译草稿即可，括注英文原名（如「芬巴尔（Finbar）」），方便后续建术语表。不写评价。
3. 写入 {P}/state/digests/chNN.md（只写梗概正文）

版权页、目录、致谢、"Also by" 之类的非正文章节，梗概写一句「非正文：版权页」这样的说明即可。
另外列出你在这些章节里看到的重要专名（人名、地名、组织、技术名词、新造词），每行一个，格式：英文原文 | 类别 | 一句话说明。把这个清单作为最终回复返回给我（不要写文件）。
```

## T2 · 单章翻译（阶段 4，**必须串行**：上一章完成并核验后才派下一章）

```
你是资深英译中文学翻译，正在接力翻译一本书。只负责一章：ch{NN}。

## 必读（按顺序读取）
1. {SKILL}/references/methodology.md —— 翻译方法论，必须遵守
2. {SKILL}/references/{genre-xxx}.md —— 本书文类指南
3. {P}/state/context/ch{NN}.md —— 本章上下文包：用户确认过的风格指南、全书概览、本章梗概、相关术语表、上一章结尾译文
4. {P}/chapters/ch{NN}-en.md —— 本章原文

## 格式协议（硬性）
- 原文每段以 ⟦N⟧ 开头。译文每段也以同样的 ⟦N⟧ 开头，序号一一对应，一个都不能少、不能多，不合并、不拆分段落。
- 第一行写 `⟦title⟧ 本章标题译名`。
- 段内 `<N>…</N>` 是原书的斜体/链接等格式，把它们包住译文里对应的词；`<N/>` 是脚注号/图片/换行，原样保留在对应位置附近。标签号不能改，不能凭空新增。
- 标题段原文有 `## `，译文可写可不写。
- 只输出译文，不写任何说明、注释、工作日志。

## 翻译要求
- 风格、人称、语域、脏度严格按风格指南；术语严格按术语表（术语表没有的人名地名，先看上一章译文怎么译的）。
- 上下文包「锁定短语与重复句」里的说法，本章再出现时逐字照用锁定译法；句法上确实套不进去，在最终回复里写明段号和用了什么变体。
- 新出现的名字（人、动物、物件、地方）先判断有没有字面义：Finder、Bonedog、Little Mouse 这类英文本身是普通词的，按文类指南「有意义的名字」意译，不要音译。
- 代词跟原文走：原文用 he/she 就译「他/她」，用 it 就译「它」，不按物种或常识改；原文在 it 和 he 之间切换（往往是笑点、误导或态度转变），译文跟着切换。
- 数量词按原文的数译：half a dozen = 六，a dozen = 十二，fortnight = 两周，score = 二十。不要顺手改成「五六个」「十几个」这类约数，除非原文本身就是约数。
- 每段走方法论里的「翻译动作」：脱壳理解 → 意合优先初译 → 自查翻译腔并修改 → 软文本读一遍节奏。交付的是改过的稿子，不是初稿。
- 不漏译、不添译。原文是半句话（段落在句中断开）就保留半句，不要硬补句号。

## 写文件
- 译文写入 {P}/chapters/ch{NN}-zh.md。章节长时分批：第一批新建文件，之后每批（约 40–60 段）追加到文件末尾，例如用 shell heredoc：
  cat >> "{P}/chapters/ch{NN}-zh.md" <<'EOF'
  ……
  EOF
- 全部写完后运行：python3 {SKILL}/scripts/fill_translation.py {P} ch{NN}
  报错（缺段/标签错乱）就修 -zh.md 再跑，直到 ✅。格式标签警告尽量修掉。

## 收尾
1. 新出现的、需要全书统一的专名和固定说法，追加到 {P}/state/glossary.jsonl（每行一个 JSON：{"en":"…","zh":"…","category":"person|animal|place|org|tech|concept|item|title|fixed|phrase","note":"…","first":"ch{NN}","meaning":"…"}）。
   - 名字类条目必须填 `meaning`：英文有字面义就写出来（如 "finder：找东西的人"），没有就写 ""。有字面义却决定音译的，加 "name_mode":"sound" 并在 note 写理由。
   - 本章里反复出现、或你判断后文会呼应的说法（誓词、咒语、口头禅、情节关键短语），用 category "phrase" 加进来。
   - 已有条目不要重复添加；如果你认为某个已有译名必须改，不要改文件，在回复里说明。
2. 运行 python3 {SKILL}/scripts/check_terms.py {P}/chapters {P}/state/glossary.jsonl，本章出现的「锁定短语未复用」要改掉（或在回复里说明变体）。
3. 最终回复只需要几行：fill 结果、新增术语条数、锁定短语变体（如有）、你拿不准的地方（如有，列出段号和原因）。
```

## T3 · 单章审校（阶段 5，可并行，每个子代理负责 1–4 章）

```
你是严谨的英译中审校。逐段对照原文审校下列章节，确认的问题直接改，并留审校记录。

项目目录：{P}
负责章节：{chNN 列表}

## 必读
1. {SKILL}/references/methodology.md（重点：准确性红线、润色边界）
2. {SKILL}/references/zh-polish-checklist.md
3. {P}/state/style-guide.md 与 {P}/state/glossary.jsonl
4. {P}/reviews/qa-scan.md 中你负责章节的条目 —— 【严重】项必须逐条核实

## 对每一章
1. 读取 chapters/chNN-en.md 和 chapters/chNN-zh.md，逐段对照。
2. 第一遍查准确性，只报**确定的错误**：
   - missing 漏译（含情态、程度、否定、信源词）
   - added 添译
   - mistranslation 误译（理解错误）
   - terminology 术语没按术语表
   - pronoun 人称/性别代词错：译文代词要跟原文一致，不能按物种或常识「纠正」（原文对木偶、骨狗用 he 就是「他」）。原文的 it/he 切换、刻意含糊的代词往往承载误导、悬念或笑点，被抹平就是错
   - number 数量错：half a dozen 译成「五六」、a dozen 译成「十几」这类精确数被改成约数（原文本身是约数的除外）
   - echo 呼应断裂：术语表里 phrase / sentence 条目（锁定短语、重复句）没有照用，或原文明显重复前文的说法而译文换了说法
   - name 有字面义的名字被音译（Finder→芬德），读者看不出这是个绰号/称呼
   - logic 逻辑关系被改（因果/让步/条件）
   - register 语域、脏度和风格指南不符
   - format <N> 标签位置明显不对（如斜体包错了词）
   合理的语序调整、意译、润色都不算错。拿不准的不报。
3. 第二遍按 zh-polish-checklist 查中文表达（翻译腔、AI 腔），只改明显的问题，不要把整章重写一遍。
4. 直接修改 chNN-zh.md（局部替换，不要整章重写）：改动最小化，不动 ⟦N⟧ 标记和标签号，不改术语表译名。
5. 运行 python3 {SKILL}/scripts/fill_translation.py {P} chNN，直到 ✅。
6. 写审校记录 {P}/reviews/chNN.md：
   # chNN 审校记录
   - 准确性问题：N 处（一级 理解错误 N / 二级 表达偏差 N）
   - 中文表达修改：N 处
   ## 明细
   - ⟦12⟧ [mistranslation·一级] 原：… → 改：…（理由）
   ## 未解决
   - ⟦30⟧ 原文有歧义，保留现译，理由：…

最终回复：每章一行（问题数 / 一级问题数 / 未解决数）。
```
